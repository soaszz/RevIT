### 8.3 Analysis of Audit Findings
1. **Disk Data Integrity**:
   - The database table `question_attempts` was **never corrupted or overwritten**. In all conflict cases (Tests 3, 4, 5, 6), the existing stored attempt remained 100% intact with its original question ID, user ID, session slot, answer, and digest.

2. **Defect in RPC Return Value & Cross-Tenant Leak (Test 5)**:
   - When User 2 invokes `commit_verified_study_batch` passing an attempt ID belonging to User 1, PostgreSQL executes `ON CONFLICT (id) DO UPDATE SET verified_at = coalesce(...) RETURNING *`.
   - Because `ON CONFLICT` does not check `user_id = p_owner`, the RPC executes the update and **returns User 1's attempt record to User 2**.

3. **Silent Acceptance of Conflicting Payloads (Tests 3, 4, 6)**:
   - When a caller re-sends an attempt ID with a completely different answer or digest, the SQL function does not raise an error or conflict code. It silently returns the old record, obscuring caller errors.
